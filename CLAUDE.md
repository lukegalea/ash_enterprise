## About this repository

A reference Ash/Phoenix enterprise application template. The architecture is argued in `docs/manifesto/` and the
specific decisions are recorded in `docs/adr/`. **Read `docs/manifesto/00-index.md` before making architectural
changes** — several things here look unusual on purpose, and the reasoning is written down.

## Environment

Everything runs inside `devenv`. Do not invoke `mix` directly — it will not find the right Elixir, and it will write to
`~/.mix` instead of the project-local `MIX_HOME`.

```bash
devenv up -d                       # start Postgres (infrastructure only)
devenv shell -- mix test           # run anything inside the environment
devenv shell -- iex-server         # start Phoenix in IEx
devenv shell -- check              # the full local quality gate
```

**Postgres port is dynamic.** devenv shifts it when 5432 is taken (Docker, another project). Never hardcode it — read
`$PGPORT`, which `enterShell` resolves from the running cluster's `postgresql.conf`. `config/dev.exs` and
`config/test.exs` already do this.

**Do not run `mix phx.server` as a devenv process.** It holds the `_build` lock and blocks every other mix command.
That is why `processes.phoenix` is deliberately absent from `devenv.nix`.

## Non-negotiables

1. **Every resource uses `AshEnterprise.Platform.Resource`.** That is where audit, telemetry, ownership, tenancy, soft
   delete and policies come from. Opting out is explicit and local (`audit: false`), never silent.

2. **Never use `forbid_if` for row access.** The authorization model is a pure union of grants
   (`docs/manifesto/03-authorization-is-data.md`). A single `forbid_if` breaks additivity and reintroduces
   order-dependence. `forbid_if` is only for concerns that are not row access — a disabled account, a dead tenant.

3. **Policy checks must never query.** Everything they need — team ids, business-unit subtree, privilege map, reporting
   chain — is precomputed once per request into `AshEnterprise.Security.ActorContext`. A check that issues a query is a
   bug, not a slow path.

4. **Run `mix ash.codegen <name>` after changing any resource.** Ash derives migrations as a diff against the resource
   snapshots; forgetting means the schema silently drifts. `mix ash.codegen --check` gates CI.

5. **Do not hand-write migrations.** Change the resource and regenerate.

6. **`priv/cdm/schemaDocuments/` is vendored third-party content** (Microsoft CDM, CC-BY-4.0, pinned commit). Never edit
   it. To change a generated resource, edit the resource. See `priv/cdm/ATTRIBUTION.md`.

## Adding a resource

Prefer adopting from the CDM corpus over inventing entities — see `docs/manifesto/02-schema-commons.md` for why, and
`mix cdm.gen.resource` for how. Delete the columns you do not need; CDM entities are wide because they serve everyone.

## MCP

`.mcp.json` wires **Tidewave** (`project_eval`, `get_ash_resources`, `execute_sql_query`, version-pinned `get_docs`).
It talks to the running dev server, so start `iex-server` first or it shows disconnected. `project_eval` is usually a
faster way to answer a question about this app than reading files.
